# Testing contracts and CI gates

The testing review identified missing enforcement, not demonstrated logic defects.
The changes below add independently checked evidence. A numerical review score
is not inferred from the number of tools installed or a successful test count.

## Gate map

| Review gap | Committed check | CI execution and failure policy |
| --- | --- | --- |
| Coverage | pytest-cov/coverage.py branch measurement; `scripts/check_coverage.py` | Every Quality matrix job fails below 95% statements, 90% branches, or 94% combined. Each production module must meet 90% statements and 80% branches. Missing modules/branch evidence fail. |
| Mutation | `scripts/mutation_gate.py`, `tests/quality/mutation.json` | Cosmic Ray `AddNot` mutates 12 selected production predicates. All 12 must be killed after a passing baseline. Surviving mutants, timeouts, and infrastructure/collection errors fail. |
| Properties | `tests/property/test_semantic_invariants.py` | Deterministic Hypothesis examples check alias equivalence/cycles, Cartesian-product graph paths, budgets, and nonsemantic source padding. |
| Fuzzing | `tests/fuzz/harness.py`, `test_fuzz_corpus.py` | Bounded generated bytes and explicit malformed/encoding/nesting/cycle corpus inputs run in every Quality job. Unexpected exceptions or broken references fail. |
| Real SDK regressions | `scripts/package_regressions.py`, `tests/fixtures/package_contracts.json` | Separate CI jobs download pinned OpenAI 3.26.0, openai-agents 0.23.1, and NumPy 2.5.3 wheels and scan them without imports. |
| Live `--latest` | `.github/workflows/ecosystem.yml` | Real CLI acquisition, analysis, export, contracts, and temporary-directory cleanup run on every `main` push, weekly, and on demand. Acquisition failures fail visibly. |
| Semantic drift | `tests/regression/golden/contract_inventory.json` | Every CSV, JSON/JSONL artifact and SQLite schema/table is compared to a reviewed controlled-source oracle. All 14 artifacts participate. |
| Differential oracle | `tests/differential/test_runtime_oracle.py` | CPython introspection of controlled synthetic source checks parameter kinds/defaults, binding, docs, async flags, C3 owners, fields, and required keys. |
| Performance budgets | `scripts/performance_gate.py`, `tests/quality/performance.json` | Dedicated job fails latency, traced Python allocation, throughput, scaling, output-size, or semantic checks. |
| Filesystem adversaries | `tests/integration/test_filesystem_boundaries.py` | Real internal/dangling/cyclic symlinks, artifact links, a link inserted during staging, traversal names, and output conflicts. Linux runs all cases; Windows skips link cases only when privilege is unavailable. |

Quality runs on Linux and Windows for Python 3.11 and 3.14, and on Linux for
3.12 and 3.13. Dependency auditing includes the mutation extra. JSON/XML coverage,
mutation, performance, and compact SDK reports are retained as Actions artifacts.
The jobs fail normally; no `continue-on-error` or success-on-network-error path is
configured. Required branch status selection remains a hosted repository control.

## Local reproduction

```bash
python -m pip install -e ".[dev,mutation]"
python scripts/check.py --artifacts dist
python scripts/mutation_gate.py --report .cache/mutation-gate.json
python scripts/performance_gate.py --report .cache/performance-gate.json
python scripts/package_regressions.py --mode pinned --report .cache/pinned.json
python scripts/package_regressions.py --mode latest --report .cache/latest.json
```

The default pytest invocation measures the complete package, including unimported
production modules; no files or uncovered branches are excluded. `check.py`
additionally enforces separate statement/branch and per-module thresholds.
Focused local investigations can use `python -m pytest --no-cov PATH`; this does
not satisfy the complete coverage gate. The Hypothesis `ci` profile uses 75
examples per generated test, deterministic generation, no example database, and
no timing deadline. Temporary files belong to each generated example.

Replay saved fuzz inputs with:

```bash
python tests/fuzz/harness.py FILE [FILE ...]
```

`fuzz_one(bytes)` is reusable by a coverage-guided engine, but the checked-in CI
campaign is bounded Hypothesis/corpus fuzzing, not a claim of exhaustive or
continuous libFuzzer exploration. Input bytes are never executed. The runtime
oracle executes only constrained test-owned source and never imports a target
SDK, downloads credentials, evaluates its defaults, or calls its methods.

## Golden changes and package contracts

The golden JSON is a small reviewed test oracle, not a generated third-party
inventory. It covers nonempty definitions, overloads, aliases, all parameter
kinds, inheritance, outputs, stubs, transport, cycles, and malformed-source
diagnostics. Tests enforce minimum fixture counts to prevent vacuous success.
SQLite is compared by schema and sorted rows, not engine-specific binary pages.
Only the checkout-specific root is replaced with `<controlled-source>`.

Regenerate after reviewing an intentional semantic change:

```bash
python tests/regression/golden_support.py --update
git diff -- tests/regression/golden/contract_inventory.json
```

Ordinary tests never rewrite snapshots. Inspect every changed definition,
parameter, field, status, diagnostic, and table before accepting the new oracle.

Pinned and latest SDK jobs check representative method contracts, retained
definition/output cardinality, methods.csv/SQLite identity equality, implicit
receiver exclusion, output joins, SQLite integrity and foreign keys. Representative
response fields include OpenAI Responses/ChatCompletion and Agents RunResult;
NumPy assertions include ndarray stub parameters and native diagnostics. Source
count floors detect large omissions, not complete runtime API coverage. Live
upstream changes can legitimately require a reviewed contract update. Network
outages remain visible in their separate jobs and do not alter offline tests.

## Budget scope and current evidence

Performance uses 16 and 64 generated modules, eight callable methods per module,
and 32 shared response fields. It times the full scan/resolve/export pipeline
with `perf_counter_ns`; memory is measured separately using `tracemalloc`.
Three samples follow a warmup. Correct counts/fields, absent diagnostics, and
all-artifact repeat hashes prevent incomplete fast output from passing.

The committed limits are 10 seconds, 96 MiB traced Python allocations, at least
100 emitted methods/second, 64 MiB exported bytes, and at most 7x latency/6x
memory for 4x modules. These are coarse regression budgets for shared CI runners,
not an SLA. Tracemalloc does not measure native SQLite allocations, process RSS,
or heap fragmentation. Changes to budgets require an explained workload and
measurement comparison; do not loosen a budget solely to hide a regression.

On Windows / CPython 3.13.13, the initial campaign killed 12/12 selected mutants
with zero infrastructure failures. The performance workload emitted 512 methods
at a 0.986-second median, with 9.37 MiB traced peak, 2.28x latency and 3.62x
memory for 4x modules. The pre-change 178-test suite measured 94.74% statements
and 87.74% branches. The expanded suite passes 268 tests on Windows (five link
cases skip solely for unavailable symlink privilege). It measures 97.60%
statements / 92.78% branches on Python 3.13 and 97.54% / 92.64% on Python 3.12.
All 14 golden artifacts also match on Python 3.11 and 3.14. Pinned and live
latest runs pass for all three reviewed SDKs. Exact CI measurements are emitted
by each run; Linux must execute the five additional link cases.

The mutation score applies only to the twelve reviewed predicate inversions. It
does not cover all statements, mutation operators, or equivalent mutants. Golden
and differential fixtures cover supported constructs, not arbitrary metaclasses,
native behavior, or generated APIs. None of these gates proves correctness for
every Python module or warrants a predetermined reviewer score.
